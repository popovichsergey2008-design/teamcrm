# Видение: ИИ-нативная CRM (стратегия продукта)

> Синтез стратегического анализа рынка CRM в эру ИИ + карта «что у нас уже есть / что нужно» + роадмап. Документ — верхнеуровневый; конкретные фичи описываются отдельными спеками (`enh-*`).

## 1. Тезис

Потребность в управлении **не исчезнет**, но софт превратится из **«цифрового склада»** (пассивный инструмент, куда люди вручную заносят данные) в **«цифровой мозг компании»** (активный агент, который делает рутину, а человек подтверждает). Люди перестанут хотеть «работать в программе» — они захотят, чтобы «программа работала на них».

## 2. Почему CRM/таск-менеджер останется нужен (даже при сильном ИИ)

- **Единый источник истины (System of Record).** Бизнесу нужно место, где официально зафиксировано «сделка закрыта / счёт оплачен / задача выполнена» — структурированная БД, доступная бухгалтерии, юристам, владельцу. ИИ выполняет работу, но **результат должен где-то храниться регламентированно**.
- **Человеческий контроль и ответственность.** ИИ галлюцинирует; в бизнесе цена ошибки — деньги/репутация. Нужен дашборд, чтобы проверить, что сделал ИИ, и нажать «Одобрить». → **human-in-the-loop как инвариант.**
- **Среда коммуникации людей.** Бизнес — отношения. Софт будущего — пространство, где люди договариваются и принимают стратегические решения.
- **Комплаенс (152-ФЗ / GDPR).** Данные клиентов хранятся по правилам; хаотичный чат с нейросетью это не заменяет.

## 3. Как ИИ «убивает» старый тяжёлый софт (наше окно против Битрикса)

Битрикс — мощный, но тяжёлый монолит; чтобы изменить логику автоматизации, часто нужно сложное программирование. Наш шанс:

- **Zero-UI / команда на естественном языке.** Вместо 20 полей карточки — «Продал Иванову 5 тонн цемента, доставка в четверг» → ИИ сам создаёт сделку/задачу/счёт. Софт становится «невидимым».
- **От инструмента к агенту.** Не пассивный «молоток», а активный «подмастерье»: сам напомнит, подготовит черновик, предложит действие.
- **Автоотчётность на NL.** «Почему упала прибыль?» → мгновенный аналитический ответ по тысячам задач/переписок.
- **Скорость адаптации.** Логика через **версионируемые промпты** меняется за часы, а не месяцы (в отличие от битриксового монолита).

## 4. Главный риск и наша защита

**Риск:** ИИ встроят прямо в ОС/почту (Google/Apple/Microsoft, OpenAI/Anthropic) — если почта сама заносит задачи в календарь, зачем отдельное приложение.

**Защита — специализация и бизнес-логика.** Общий ИИ знает всё понемногу, но не знает нюансов *вашего* процесса, системы мотивации *ваших* сотрудников, цепочки поставок *ваших* товаров. Плюс: единый источник истины, комплаенс, командная среда, **версионируемая доменная логика (промпты)**. → Не «Битрикс с кнопкой ИИ», а система, **построенная вокруг ИИ**.

## 5. Карта: что у нас УЖЕ есть vs что нужно

| Направление (из анализа) | Статус у нас | Где |
|---|---|---|
| **Управление знаниями (для людей и обучения ИИ)** | ✅ Готово | База знаний RAG (K1-K3): индексация задач/комментов/файлов/регламентов, семантический поиск, AI Brain с цитатами, разрез по проектам |
| **Трекинг затрат на API (Claude/GPT токены)** | ✅ Базово | `ai_usage` метеринг (токены/стоимость/cache-hit), `GET /api/ai/usage` |

| **Авто-создание задач из внешних источников** | ✅ Частично | Импорт из Битрикса (задачи/комменты/файлы/лента, live-события); AI-стендап (голос→действия по задачам) |

| **Версионирование промптов (PromptOps)** | ❌ Нужно | Промпты сейчас захардкожены (Brain SYSTEM, парсер стендапа). См. `enh-07-prompt-versioning.md` |
| **Zero-UI / NL-команда («создай сделку …»)** | ❌ Нужно | Отдельная спека (NL-command → интенты → действия с подтверждением) |
| **Авто-создание задач из переписок (почта/чат)** | ❌ Нужно | Расширение: коннектор почты/мессенджера → интент → задача+черновик |
| **Оркестрация ИИ-агентов (агент-исполнитель)** | ❌ Отдельный трек | Codex/Claude-агент в песочнице (обсуждали): задача→агент→результат в комментарий→ревью |
| **Аудит качества работы ИИ** | ⚠️ Заложено | ai_usage есть; оценка качества (👍/👎, доля переделок) — в PromptOps P2 |
| **Метеринг «человеко-часы + токены ИИ»** | ✅ Частично | тайм-трекер (Этап 2) + ai_usage; свести в единый «cost of work» — доработка |

**Вывод:** мы уже заметно ИИ-нативнее классического Битрикса (RAG-знания, AI Brain, co-pilot, метеринг, BYOK). Ключевые пробелы для «построенности вокруг ИИ»: **PromptOps**, **NL-команда/Zero-UI**, **авто-задачи из переписок**, **оркестрация агентов**.

## 6. Роадмап ИИ-нативных фич (по приоритету)

1. **PromptOps — версионирование промптов** (`enh-07`). Фундамент: вся ИИ-логика становится управляемой/тестируемой/откатываемой без релиза кода. Делать первым — на нём стоит всё остальное.
2. **NL-команда / Zero-UI.** Строка «скажите, что сделать» → ИИ распознаёт интент (создать задачу/сделку/напоминание) → guarded-выполнение с подтверждением. Использует PromptOps-промпты.
3. **Авто-создание задач из переписок.** Коннектор почты/мессенджера (как Битрикс-коннектор) → интент → задача + черновик решения → человек утверждает.
4. **Усиление ИИ-ассистента менеджера.** На базе Этапа 4: проактивные рекомендации по перераспределению нагрузки, риск-алерты, «клиент недоволен ценой — подготовил черновик скидки».
5. **Единый «cost of work».** Свести человеко-часы (тайм-трекер) + токены ИИ (ai_usage) в одну экономику задачи/проекта.
6. **Оркестрация ИИ-агентов** (агент-исполнитель, отдельный трек): песочница + guarded-ревью; «нейросеть написала код → авто-задача на ревью senior-у».

## 7. Инварианты ИИ-нативной архитектуры (наши принципы)

- **AI-first, единая точка egress** (`AiService`) — маскирование PII неотключаемо; тиринг моделей; BYOK per-tenant.
- **Human-in-the-loop** — ИИ предлагает, человек подтверждает (паттерн co-pilot/стендапа); ничего не «применяется» молча.
- **Метеринг всего** — токены и стоимость durable (`ai_usage`), для биллинга и оптимизации.
- **Версионируемая доменная логика** — промпты как код (PromptOps): тест, откат, A/B, аудит.
- **Изоляция** — tenant + доступ; RAG не обходит RBAC; клиент не видит экономику.

## 8. Окно возможностей

**2–4 года**, пока тяжеловесы (Битрикс и др.) медленно адаптируются, а ОС-встроенный ИИ ещё не знает доменных нюансов. Стратегия: **начать строить ИИ-нативное ядро сейчас**, зафиксировать доменную бизнес-логику в версионируемых промптах, экономить когнитивный ресурс менеджера («программа работает на них»).
