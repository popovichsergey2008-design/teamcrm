# ТЗ-2, Этап 6 — Календарь, шаг 1: события, участники, экран

Продолжение разбора `tz2-05-calendar-and-feed.md`. Здесь — то, что делаем в первом заходе,
и решения заказчика, на которых оно стоит.

## Решения заказчика (25.08.2026)

1. **Личный календарь у каждого + общий календарь компании.** Двух видов достаточно.
2. **Календари проектов — не делаем.** Отложены осознанно: смысл их в том, чтобы событие
   проекта («планёрка по Аэросу») видела вся команда проекта без ручного выбора участников.
   Вернёмся, когда станет понятно, нужно ли это.
3. **Рабочие часы и праздники задаёт владелец или его помощник.** Отсюда отдельная работа:
   право «как у владельца» должно выдаваться человеку осознанно.
4. **Внешний гость — только по нашей ссылке на созвон.** Приглашений письмом с `.ics` на
   почту гостя не делаем: у нас уже есть гостевой вход в комнату, и вторая дверь в ту же
   встречу — лишняя сущность и лишний способ ошибиться.

## Права владельца — что чиним заодно

Сегодня роль меняет `PATCH /users/:id` с доступом у ролей `owner` и `manager`. То есть
руководитель может выдать себе роль владельца и получить доступ к интеграциям (а там ключи
чужих систем) и к расходам на ИИ. Это дыра, а не гибкость.

Делаем так:
- **Назначать роли может только владелец.** Руководитель по-прежнему заводит людей и правит
  их данные, но роль — не трогает.
- **Владельцев может быть несколько** — это и есть «помощник владельца». Отдельной роли не
  заводим: она означала бы почти те же права, но с другим названием, и через месяц никто не
  вспомнит, чем они отличаются.
- **Основателя нельзя понизить.** Он уже вычисляется (первый по времени владелец, признак
  `isFounder` в профиле). Второй владелец не должен иметь возможности выкинуть первого.

Полноценная матрица прав по возможностям — отдельный большой разговор; сейчас важнее закрыть
эскалацию, чем строить систему прав, которой никто не пользуется.

## Модель данных

Миграция `0047_calendar.sql`:

```sql
calendar_events
  id, tenant_id, scope ('personal' | 'company'), owner_id,
  title, description, location,        -- место: адрес или произвольный текст
  meet_room_id  VARCHAR(64) NULL,      -- наш созвон: комната, куда ведёт кнопка «Начать созвон»
  starts_at, ends_at, all_day BOOLEAN,
  color VARCHAR(16) NULL,
  is_private BOOLEAN,                  -- другие видят занятость без названия
  created_by, created_at, updated_at

calendar_participants
  event_id, user_id, status ('invited' | 'accepted' | 'declined'),
  is_organizer BOOLEAN, responded_at
  PRIMARY KEY (event_id, user_id)

org_work_settings            -- одна строка на организацию
  tenant_id PK, work_start (time), work_end (time),
  weekend_days INT[],        -- 0=вс … 6=сб
  holidays DATE[]            -- нерабочие даты
```

Почему участники отдельной таблицей, а не массивом в событии: у каждого свой ответ на
приглашение, и его нужно менять по одному человеку, а не переписывать всё событие.

## Что показывает экран

Раздел **«Календарь»** — подпунктом внутри «Фокуса дня» (в ТЗ ровно четыре пункта меню,
пятый не добавляем; «Встречи» так же живут внутри «Чатов»).

- Виды: **неделя** (основной), день, месяц, список.
- Сетка с рабочими часами: нерабочее время и выходные приглушены — по настройке организации.
- Создание щелчком по свободному месту, редактирование — по клику на событие.
- **Задачи со сроком** — отдельным слоем, включается галочкой (как в Битриксе). Данные уже
  есть: `tasks.deadline_at`.
- Приглашения: счётчик неотвеченных, кнопки «Принять» / «Отклонить» на самом событии.
- Приватное событие видно другим как «Занято» без названия.

## Границы шага

**Входит:** события личные и компании, участники с ответами, четыре вида, рабочие часы и
праздники организации, задачи слоем, кнопка «Начать созвон» у события, счётчик приглашений,
запрет назначать роли не-владельцу.

**Не входит (следующие шаги):** напоминания и `.ics` (шаг 2), занятость коллег при выборе
участников и блокировка пересечений (шаг 2), повторяющиеся события (шаг 4), переговорные,
синхронизация с внешними календарями, лента компании.

## Проверки

- e2e: событие видят только участники; чужая организация не видит ничего; приватное отдаётся
  без названия; ответ на приглашение меняет только свою строку.
- e2e на права: руководитель не может сменить роль, владелец может; основателя понизить нельзя.
- Юнит: раскладка события по сетке недели (события на границе суток и «весь день» — то место,
  где календари ошибаются молча).
