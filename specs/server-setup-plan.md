# План настройки сервера для TEAMCRM

> Составлен после фактического подключения к серверу и обследования (read-only). Сервер оказался **не чистым** — это нагруженный production-хостинг под FASTPANEL с чужими сайтами и почтой. План адаптирован под эту реальность и **отличается** от «чистого» Этапа 0 спеки.

## 1. Что фактически на сервере (инвентаризация)

**Хост:** Contabo, IP `31.220.82.35`, Debian 12 (bookworm), 8× AMD EPYC, 23 ГБ RAM (~10 ГБ свободно), диск 1.2 ТБ (занято 55%, ~507 ГБ свободно), swap 0, аптайм 182 дня, **185 необновлённых пакетов**.

**Это shared-хостинг под FASTPANEL 1.11 + Webmin.** Уже работает и обслуживает посторонние проекты:

| Категория | Что крутится |
|---|---|
| Панели | FASTPANEL (`7777/8888`, API `5501`), Webmin (`10000`) |
| Web-стек | nginx (на `IP:80/443`), Apache (`127.0.0.1:81`), PHP 8.2-FPM |
| Базы | MariaDB (`127.0.0.1:3306`), системный Redis (`127.0.0.1:6379`), memcached |
| Почта/FTP | Exim4 (`25/465/587`), Dovecot (`110/143/993/995`), ProFTPD (`21`) |
| DNS / RTC | BIND (`53` на публичном IP), coturn (`3478`) |
| Чужие сайты | anika-property.com, austincontrarian.com, local-seo-usa.com, seo-optimization.xyz (SEO-клиенты) |

**Уже есть проект `teamconnect`** (домены `teamconnect.pp.ua`, `api.teamconnect.pp.ua`):

- это **другое приложение** — Slack-подобный командный чат (таблицы `channels`, `messages`, `meetings`, `workspaces`, `reactions`; Prisma), **не наш TEAMCRM** (в нём нет deals/projects/tasks/time_logs);
- стек: Docker `postgres:16` + `redis:7` (`/var/www/fastuser/data/teamconnect/docker-compose.yml`); Node API на `:4000`, Vite-web на `:5173` (dev-сервер), проксируются fastpanel-nginx на домены.

**Свободные порты:** `3000, 3001, 3100, 8000, 8080, 8090, 9000, 9090`.

## 2. Критический вывод

Сервер **разделяемый и боевой** — на нём живут чужие сайты, почта и FTP. Поэтому «жёсткая» настройка из Этапа 0 спеки (включить `ufw` и закрыть всё, отключить `PermitRootLogin`, массовый `apt upgrade`, перезагрузка) **применяться не должна** — это с большой вероятностью оборвёт чужие сервисы и заблокирует доступ. Подход здесь — **аддитивный и изолированный**: добавляем стек CRM, ничего чужого не трогаем, безопасность наводим точечно.

## 3. Проблемы безопасности (найдены при обследовании)

| Severity | Проблема | Примечание |
|---|---|---|
| 🔴 высокий | Postgres `teamconnect` слушает `0.0.0.0:5432`, пароль `teamconnect/teamconnect` | БД с тривиальным паролем открыта в интернет |
| 🔴 высокий | Redis (docker) `0.0.0.0:6380` без пароля | открыт в интернет |
| 🔴 высокий | нет хостового фаервола (`ufw` нет, INPUT policy ACCEPT) | внешний доступ ограничен только тем, на что биндятся сервисы |
| 🟠 средний | root-пароль передан в открытом виде; `PermitRootLogin yes`, парольная авторизация | считать пароль скомпрометированным |
| 🟠 средний | Webmin `0.0.0.0:10000`, FASTPANEL `8888/7777`, Vite dev-сервер `5173` — наружу | админ-панели и dev-сервер не должны торчать в интернет |
| 🟡 низкий | 185 необновлённых пакетов, аптайм 182 дня | вероятны kernel/CVE; обновлять в окне обслуживания |

> Пункты про Postgres/Redis `teamconnect` касаются **чужого** стека — их правка требует согласия владельца teamconnect (возможно, это вы же). Не трогаю без подтверждения.

## 4. Где разворачивать CRM — две опции

### Опция A — отдельный чистый VPS (рекомендуется для production)

Финансовые данные CRM с PII на одной машине с чужими SEO-сайтами, почтой и открытыми сервисами — плохой профиль риска и соответствия (152-ФЗ/GDPR). Чистый VPS позволяет выполнить Этап 0 спеки как написано (ufw, hardening, изоляция). **Рекомендация для боевого запуска.**

### Опция B — на этом сервере, изолированным Docker-стеком (для dev/демо сейчас)

Ресурсов достаточно (~10 ГБ RAM, 507 ГБ диска свободно). Подходит для разработки/демо и быстрого «доступно по IP». Стек CRM ставится отдельным `docker compose` со своей сетью и своими портами, ничего чужого не задействуя. Для production позже мигрируем на Опцию A.

## 5. Целевая раскладка стека CRM (Опция B)

Изолированный `docker compose` (каталог, например, `/opt/teamcrm` или `/var/www/<user>/data/teamcrm`):

| Сервис | Образ | Порт (host) | Доступ |
|---|---|---|---|
| `crm-postgres` | postgres:16 + pgvector | `127.0.0.1:5433` | только localhost |
| `crm-redis` | redis:7 (с паролем) | `127.0.0.1:6381` | только localhost |
| `crm-rabbitmq` | rabbitmq:3-management | `127.0.0.1:5672/15672` | только localhost |
| `crm-api` | NestJS (наш) | внутр. сеть | за reverse-proxy |
| `crm-web` | React build (статик через nginx-контейнер) | внутр. сеть | за reverse-proxy |
| `crm-edge` | nginx (reverse-proxy стека) | `0.0.0.0:8080` | **наружу по IP** |

Инварианты: все БД/брокер биндятся **только на `127.0.0.1`** (в отличие от существующего teamconnect); наружу торчит только edge-nginx на одном свободном порту; секреты — в `.env` вне git.

## 6. «Доступно по IP сейчас» — как открываем

Цель: `http://31.220.82.35:<порт>` отдаёт CRM (а пока код не готов — placeholder/обзор спеки).

1. Выбираем свободный порт (предлагаю **8080**).
2. Поднимаем edge-nginx (в составе стека CRM или отдельным контейнером), слушающий `0.0.0.0:8080`.
3. Проверяем внешнюю достижимость. Здесь ключевая зависимость — **Contabo Cloud Firewall** (внешний, настраивается в панели Contabo, не на хосте): если он включён, порт 8080 нужно явно разрешить, иначе снаружи не откроется. Нужен доступ к панели Contabo либо подтверждение, что cloud-фаервол выключен.
4. Пока приложение CRM не собрано — на 8080 публикуем статический placeholder (например, обзорную страницу спеки `specs/overview.html`), чтобы по IP уже что-то открывалось как контрольная точка.

> Бинд на отдельный порт `8080` не конфликтует с nginx FASTPANEL (он слушает `IP:80/443`) и не затрагивает чужие вхосты.

Альтернатива (если позже будет домен/субдомен): добавить вхост в FASTPANEL-nginx (`crm.<домен>`) с проксированием на edge-nginx — но это уже к доменному этапу, не «по IP».

## 7. Безопасность — что делаем точечно (без поломки чужого)

Только аддитивно и по согласованию:

1. **Свой Postgres/Redis CRM — только на localhost** (заложено в раскладке) + сильные пароли в `.env`.
2. **Сменить root-пароль** и **добавить SSH-ключ** (парольную авторизацию для root можно отключить только после проверки, что у всех админ-процессов есть ключи — иначе риск локаута; согласовать).
3. **Contabo Cloud Firewall** (внешний) — предпочтительный способ ограничить внешние порты, не трогая хостовый сетевой стек и чужие сервисы. Через него: оставить открытыми `22, 80, 443, 8080` (+ почта/ftp/dns, что нужно чужим сайтам), закрыть `5432, 6380, 10000, 5173` снаружи.
4. **Существующий teamconnect Postgres/Redis** (открытые наружу с тривиальным паролем) — отдельно согласовать с владельцем: перевести бинд на localhost и сменить пароль. Срочно по severity, но это чужой стек.
5. Обновления пакетов и перезагрузку — в согласованное окно обслуживания, не в рамках этой задачи.

## 8. Соответствие Этапу 0 спеки (и отклонения)

| Пункт Этапа 0 | На этом сервере |
|---|---|
| Три окружения dev/staging/prod | этот сервер пригоден как dev/staging; prod — рекомендуется отдельный VPS (Опция A) |
| Хардненинг ОС, ufw, отключение root | **не применяем хостовой ufw** (сломает чужое); вместо — Contabo Cloud Firewall + bind на localhost + reverse-proxy; смена пароля/ключи — по согласованию |
| Docker Compose, ядро хранилищ | ✔ изолированный стек CRM (pg+pgvector, redis, rabbitmq) своим compose |
| pgvector | ✔ в своём `crm-postgres` |
| CI/CD автодеплой | настраивается отдельно (push → сборка → деплой контейнеров) |
| Мониторинг, бэкапы | на хосте есть monit; бэкап БД CRM — отдельной политикой + контрольное восстановление |
| data-residency 152-ФЗ/GDPR | для боевого финучёта PII — аргумент в пользу отдельного VPS в нужной юрисдикции |

## 9. Открытые решения (нужны от вас)

1. **Что выставить по IP прямо сейчас:** существующий TeamConnect (другой продукт), placeholder/обзор TEAMCRM (наш код ещё не написан), или пока ничего.
2. **Дом для CRM:** этот shared-сервер (как dev/демо) или отдельный чистый VPS (для production).
3. **Доступ к панели Contabo** (Cloud Firewall) — есть ли он, чтобы корректно управлять внешними портами.
4. **Разрешение на security-фиксы** существующего teamconnect-стека (открытый Postgres/Redis) — это ваш проект или клиентский.
