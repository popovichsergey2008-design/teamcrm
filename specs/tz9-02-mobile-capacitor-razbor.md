## 1. Что изменилось — и это ровно то, что мы рекомендовали

| Было (RN-пакет) | Стало (Capacitor-пакет) |
|---|---|
| Отдельный React Native UI, вторая реализация каждого экрана | **Один React/TS-фронт** + мобильная раскладка + оболочка Capacitor (Kotlin/Swift только для ОС) |
| LiveKit «или WebRTC» | **mediasoup остаётся**, все упоминания LiveKit — устаревшие |
| Копия API под `/mobile/v1/*` | Существующие `/api/*` напрямую; под `/mobile/*` — только агрегаты, устройства, конфиг, ящик уведомлений, манифесты обновлений, sync |
| Магазины сначала | **Android — APK с сайта + проверка обновления в приложении; iOS — PWA до Apple Developer**, потом TestFlight |
| Полное offline-зеркало | Ограниченный рабочий набор, offline по уровням: кэш → черновики → безопасные отложенные мутации → версии → журнал изменений |
| Push как канал событий | Push — сигнал; **источник истины — серверный ящик уведомлений** с курсором; iOS-звонок — PushKit+CallKit только для нативной сборки |

Все девять «уже подтверждено» в `03_PRESTART_DECISIONS.md` совпадают с решениями заказчика от
21.09. Пакет можно брать как рабочий план без правок по существу.

## 2. Ключевые принципы пакета, которые становятся правилами для ВСЕЙ дальнейшей разработки

1. Новая функция делается один раз в общем фронте и обязана работать в трёх раскладках:
   десктоп, мобильный веб, Capacitor. Платформенный код — только там, где ОС этого требует.
2. Фронт не зовёт Capacitor напрямую — через слой `PlatformBridge` (notifications, biometrics,
   secureStorage, share, deviceInfo, appUpdate, deepLinks, callIntegration, filesystem) с
   браузерной реализацией по умолчанию.
3. Три класса изменений: UI/бизнес (уезжает сам — веб-деплой + OTA-бандл), backend-only
   (клиент не трогаем при совместимом API), native (новый APK/iOS-сборка).
4. Каждая критичная запись либо идемпотентна, либо честно «не работает offline».
5. Черновик, голосовая запись, сообщение не удаляются из-за упавшего запроса — никогда.

## 3. Аудит нашего фронта под волну 0 (проверено по коду 21.09)

Что уже есть:
- 36 медиа-запросов; на ≤720px сайдбар уже становится выдвижной панелью с кнопкой «меню»
  (`nav-open-btn`, `nav-backdrop`); есть отступы под узкий экран у панелей поддержки и чатов.
- `public/manifest.json` (standalone, иконки 192/512, тёмный фон) — **PWA «установить на
  экран» работает уже сейчас**, service worker не подключён (и пока не нужен — пакет
  предупреждает, что SW легко «застревает» на старом бандле).
- `mediasoup-client` в вебе, `getUserMedia`/`getDisplayMedia` в CallPanel, диктовка через
  MediaRecorder (`useVoiceInput`), запись клипов — всё это в WKWebView/Android WebView
  работает (iOS ≥ 14.5), проверять надо только фон/Bluetooth/маршрут звука — это и есть
  spike волны 7.
- Deep links: канонические адреса `/projects/:p/task/:t`, `/chat/:id` живут в `lib/router.ts`;
  AASA/assetlinks повесятся на них без изменения роутинга.
- Swagger поднят в `main.ts` — источник контрактов есть.

Мобильные блокеры (то, что делает волна 1):
- **Нет нижней навигации** — на телефоне разделы за «гамбургером»; пакет требует вкладки
  Фокус · Проекты · Чаты · Миты · Ещё и кнопку 🎤 под большой палец.
- **Доска — HTML5 drag-and-drop** (`ColumnView`, `ProjectsNav`): на touch не работает;
  нужен touch-перенос или альтернатива «переместить» из меню карточки (пакет: «drag/drop без
  touch alternative» — блокер).
- **158 правил `:hover`** — большинство декоративные, но меню по наведению (действия у
  сообщений/карточек) обязаны иметь tap/long-press (`MessageMenu` уже умеет long-press —
  единственное место с touch-логикой).
- **Токены в `localStorage`** (`lib/api.ts`) — для Capacitor нужен `secureStorage` через
  PlatformBridge (Keystore/Keychain), в вебе остаётся как есть.
- `window.open` — 1 место; `navigator.clipboard` — 10 мест (в WebView работает, но
  проверить в Android WebView на HTTP-контексте — у нас HTTPS, ок).
- `<table>` — 4 места (реестр задач, команда, импорты): нужен мобильный вид карточками.
- Панели, живущие «поверх» (окно чата, панель поддержки, звонок, диктовка) — на телефоне
  должны становиться полноэкранными листами с безопасной зоной под клавиатуру.

## 4. Решения, которые пакет просит зафиксировать до кода — предложения

| Пункт | Предложение |
|---|---|
| Android package id / iOS bundle id | `team.anthill.app` (домен наоборот: anthill.team) |
| Ключ подписи Android | Заводим сейчас, храним в `infra/secrets` (gitignored) + копия у заказчика; потеря ключа = нельзя обновить установленные APK |
| Домен/путь раздачи | `https://anthill.team/download` (страница + `latest.json` для проверки обновления) |
| Структура репозитория | Монорепо не переделываем (пакет: «принцип важнее структуры»): `frontend/` остаётся общим фронтом, добавляется `mobile/` с Capacitor-проектом (`android/`, `ios/`), `webDir` указывает на сборку `frontend/dist`; `PlatformBridge` — в `frontend/src/platform/` |
| OTA web-бандла | `@capgo/capacitor-updater` в **self-hosted** режиме с нашим манифестом (version, min_native, sha256, url, mandatory, rollback) — открытый код, без сторонней подписки; манифест отдаёт наш бэкенд |
| Приватность push по организации | Значение по умолчанию `sender_only` («Новое сообщение от Глеба»); настройка в разделе «Команда» → «Безопасность» у владельца: hide / sender_only / full |
| Матрица отзыва устройств | Владелец и руководитель — устройства своих сотрудников; сотрудник — только свои; техотдел платформы — не видит чужих устройств (поддержка — не админ клиента) |
| Spike mediasoup в Capacitor | Делаю я в волне 2 сразу после первой сборки оболочки (Android), до волны 7 |
| Дата Apple Developer | Не заведён; iOS = PWA. Оболочка iOS собирается и проверяется на симуляторе; TestFlight — когда появится аккаунт |

## 6. С чего начинаю

Волна 0 → волна 1: `PlatformBridge` (интерфейсы + браузерная реализация) и мобильная
раскладка веба, начиная с нижней навигации и полноэкранных листов. Это полезно немедленно
(сайт в телефоне), не требует никаких решений с ключами и аккаунтами и является общим
фундаментом для оболочек. Серверные P0 (`/mobile/config`, `mobile_devices`, отзыв админом)
пойдут следом, к моменту первой сборки APK.

**Волна 9 — работа без сети (21.09).**
- Сервер. Миграция `0119`: `tasks.version` (BEFORE UPDATE-триггер бампит версию только при
  содержательном изменении — сдвиг позиции соседей не считается) и журнал `change_log`
  (курсор = identity, `entity_type` task / task_comment / chat_message / checklist_item,
  `parent_id` — проект, задача или чат; чистится раз в час, старше 30 дней). Триггеры на
  четырёх таблицах пишут ссылки, не содержимое.
- `Idempotency-Key` (перехватчик на POST/PATCH/PUT/DELETE): ключ в Redis на сутки,
  повтор отдаёт тот же ответ, параллельный повтор — 409; Redis лёг — работаем без защиты.
- `If-Match: <version>` на `PATCH /tasks/:id` и `move`: несовпадение → 409
  `{reason:'version', expected, current, task, fields}` — сервер не перезаписывает чужое молча.
- `GET /mobile/sync?cursor&limit` → `{cursor, reset, more, changes}`: без курсора — голова
  журнала (первый заход — не история); курсор старше журнала — `reset`. Видимость — по
  проектам и членству в чатах, удаления отдаются без проверки.
- Фронт. `lib/offline-queue.ts` — очередь в localStorage: uuid записи = ключ идемпотентности,
  порядок постановки = порядок отправки, до первого «нет сети»; статусы pending / failed /
  conflict. Через очередь идут комментарии к задаче, сообщения чата и правка полей задачи
  (`api.queued`). При обрыве вызывающий получает `ApiError(QUEUED)` и очищает поле, а
  написанное висит в ленте с пометкой «ожидает сети».
- `OfflineBar` — полоса «Нет сети · N изменений ожидают отправки», лист очереди
  (повторить / убрать / отправить сейчас), `ConflictSheet` — два варианта рядом:
  «оставить мой» (та же правка поверх версии сервера) или «взять серверный». Автослияние
  не делаем: склеенное описание хуже любого из двух целиком. Конфликт при живой сети
  (карточка задачи) идёт тем же листом — правка кладётся в очередь со статусом conflict.
- `useDeltaSync` — при возврате сети / на экран после >15 с / переподключении сокета /
  после ухода очереди спрашивает журнал после своего курсора и рассылает `teamcrm:sync`;
  доска, чат и лента задачи перечитывают только то, что их касается.
- Осознанно не через очередь: перенос карточки между колонками (позиции без сервера не
  сойдутся) и файлы (вложения не хранятся в localStorage). Их без сети — обычная ошибка.
- Проверки: logic-check (`applyOutcome`, `summarize`, `queueBanner`), e2e
  `mobile-sync.e2e-spec.ts` (идемпотентность, If-Match, sync с приватным проектом) — на CI.
