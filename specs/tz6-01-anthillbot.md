# ТЗ-6 — AnthillBot: персональный AI-агент TeamCRM

Источник: `TZ/AnthillBot_Technical_Specification.md` (14.09.2026). Ключевой принцип
(разд. 68): не «ChatGPT внутри CRM», а LLM + контекст CRM + поиск + права + память +
навыки + действия + расписания. И два железных правила — **права проверяются ДО
того, как данные уходят в модель** (разд. 47), и **модель не меняет базу напрямую,
только через слой инструментов с подтверждением** (разд. 48, 12).

## Чего НЕТ (предмет ТЗ-6)

- **Единый агент**: системный контакт AnthillBot в мессенджере, кнопка в Chat Bar с
  компактным окном, полноэкранный режим, вкладки Чат · Задачи · Skills · Память ·
  История. Сейчас семь входов: «@AI», «Спросить ИИ» в Ctrl+K, «AI Секретарь»,
  «База знаний», «Проверить ИИ», «Быстрая команда», «Что я пропустил».
- **Оркестратор с инструментами** (разд. 48–49): модель выбирает инструмент и
  отдаёт структурированные параметры; исполнение — только через слой tools с
  проверкой прав и подтверждением; журнал действий `ai_actions`, undo.
- **Retrieval с ACL по человеку** (разд. 47, 55): индекс сообщений, тредов, задач,
  комментариев, сводок, стенограмм — с метаданными доступа; фильтрация до модели.
- **Контекст страницы** и «+ Контекст» (разд. 4–5): задача/проект/чат/тред/мит/файл/человек.
- **Ответы с источниками** в единой форме (разд. 8): [Открыть задачу #N], [Открыть сообщение], [Открыть мит].
- **Сессии** AnthillBot: история, продолжение, «+ Новый разговор», редактирование
  запроса, «Остановить», 👍/👎 с причиной.
- **Scheduled Tasks** агента (разд. 15, 58): «каждый понедельник в 9:00 — просроченные».
- **Память** (разд. 20–21, 57): предпочтения и темы, экран управления, отключение.
- **Skills** (разд. 16–19, 59): каталог, автоподбор, создание через диалог.
- **Файлы** (разд. 23): PDF/TXT/CSV/картинки — сводка, вопросы, извлечение задач.
- **@AnthillBot в каналах** с изоляцией приватного контекста (разд. 33–34).
- **Custom Responses** администратора (разд. 38), системные подсказки (разд. 37).
- **Deep Research, Web Search, интеграции** (разд. 25–28) — MVP 3.
- **Администрирование**: включить/выключить, группы, лимиты, usage, ошибки (разд. 52–53).

## Архитектурные решения

### Р1. AnthillBot — одна дверь над существующим, а не восьмой ИИ

Новый модуль `anthill` — оркестратор. Он НЕ переписывает `nl`, `chats-ai`,
`knowledge`, `assistant`, `meetings`: они становятся его **инструментами**. Прежние
входы остаются работать (ничего не ломаем), но постепенно ведут к AnthillBot:
«@AI» в чате = канальный AnthillBot, «Спросить ИИ» в Ctrl+K = окно AnthillBot,
«AI Секретарь» = вкладка Activity AnthillBot.

### Р2. Слой инструментов — единственный путь к данным и действиям

```
запрос → orchestrator → intent (модель, structured output)
       → tool (search_tasks | get_task | search_messages | get_meeting | summarize_chat |
                create_task | update_task | create_reminder | send_message | …)
       → каждый tool сам проверяет права (тем же кодом, что и обычные ручки API)
       → write-tools возвращают preview, исполняются только после подтверждения
       → ai_actions (журнал), undo где возможно
```

Модель никогда не получает «всё»: tool отдаёт ей ровно то, что человек и так
видит на экране. Это и есть разд. 47 — «фильтрация до передачи контекста».

### Р3. Retrieval с ACL — расширение `knowledge`, не новая система

Индекс `knowledge_chunks` уже есть (pgvector, `access_scope`). Добавляем типы
источников (сообщения, треды, задачи, комментарии, сводки, стенограммы) и **ACL-
метаданные**: `chat_id` / `project_id` / `task_id` во фрагменте, а выборка
соединяется с правами человека (участник чата, проект команды) — в SQL, до модели.
Семантика + ключевые слова (существующий `search`) → фильтр прав → релевантные
фрагменты + свежий контекст + сводка → модель (разд. 56).

### Р4. Данные агента — отдельные таблицы, по ТЗ

`ai_sessions`, `ai_messages` (наследуют `brain_*` — переименовываем, историю
сохраняем), `ai_actions`, `ai_memories`, `ai_scheduled_tasks`, `ai_skills`,
`ai_custom_responses`, `ai_feedback`. Память — отдельная сущность (разд. 57), не
смешивается с сообщениями.

### Р5. Потоковый ответ и «Остановить»

`generateStream` в провайдере уже есть. Ответ идёт по SSE (`GET /anthill/sessions/:id/stream`)
с этапами «Ищу…», «Анализирую N задач…», «Формирую…»; отмена — закрытие потока,
набранная часть остаётся (разд. 43, 63).

### Р6. Бот в мессенджере — системный контакт, а не настоящий пользователь

В списке чатов и Chat Bar — контакт «AnthillBot · AI-помощник TeamCRM», открывает
окно агента (не обычный чат). В группах и каналах — упоминание `@AnthillBot`
(нынешний `@AI`): ответ в ленту, контекст — только этот чат и то, что доступно
всем его участникам; приватная память инициатора в канал не попадает (разд. 34).

## Этапы

### Этап 1 — MVP 1: агент, поиск, источники, задачи с подтверждением, напоминания
1. Модуль `anthill`: оркестратор, реестр инструментов (read: search_tasks, get_task,
   search_messages, get_chat_summary, get_meeting, get_project, who_free; write:
   create_task, create_reminder), structured output, `ai_actions`.
2. Сессии и сообщения (`ai_sessions`/`ai_messages` из `brain_*`), SSE-стриминг, «Остановить».
3. Retrieval с ACL: индексация сообщений, тредов, задач, комментариев, сводок митов
   (фоновый воркер, инкрементально), выборка с правами.
4. Интерфейс: контакт AnthillBot в мессенджере и Chat Bar, компактное окно поверх CRM,
   полноэкранный режим, контекст страницы + «+ Контекст», ответы с кнопками-источниками,
   preview действия [Создать] [Редактировать] [Отмена], голосовой ввод, история сессий,
   «+ Новый разговор», 👍/👎.
5. «Что я пропустил» / сводки — через существующие `chats-ai.digest` и `evening`
   как инструменты; ответ в форме разд. 9.

### Этап 2 — MVP 2: расписания, память, навыки, файлы, документы, каналы
1. Scheduled Tasks агента: разбор расписания из речи («каждый понедельник в 9:00»),
   планировщик, вкладка «Задачи» (активные/пауза/завершённые, следующий запуск,
   последний результат), результат — сообщением в сессию + уведомление.
2. Память: `ai_memories` (preferences / topics), автосбор с выключателем, экран
   «Память» (посмотреть, исправить, удалить).
3. Skills: сущность, каталог (мои / компании / рекомендованные), автоподбор по запросу,
   создание через диалог с preview; стартовый набор: еженедельный отчёт проекта,
   подготовка к миту, проверка просроченных, задача разработчику.
4. Файлы: PDF/TXT/CSV/картинки из вложений — сводка, вопросы, извлечение задач
   (`file-text` уже разбирает текст; картинки — через мультимодальную модель).
5. Документы: отчёт/Markdown/CSV/заметка — сначала preview, потом сохранить (в файлы
   задачи или заметки) или отправить в чат.
6. `@AnthillBot` в каналах с изоляцией; системные подсказки (разд. 37); Custom
   Responses администратора (разд. 38).
7. Write-инструменты второй волны: update_task, set_assignee, set_deadline,
   set_priority, add_comment, send_message, create_meeting, pin_chat, add_member.

### Этап 3 — MVP 3: глубокий анализ, веб, интеграции, администрирование
1. Deep Research: многошаговый план по нескольким проектам/чатам/митам с прогрессом,
   структурированный отчёт (выводы, факты, риски, рекомендации, источники).
2. Web Search — выключатель администратора, «Источник: Интернет» в ответе.
3. Интеграции как tools: Google Calendar / Gmail / Drive первыми (вопрос В4).
4. Администрирование: включение, группы пользователей, лимиты (запросы, контекст,
   файлы, расписания, навыки), usage, ошибки; мобильная раскладка, push по расписаниям.

## Вопросы к заказчику

**В1. Имя и единство.** AnthillBot заменяет все нынешние входы к ИИ по имени:
«AI Секретарь» становится вкладкой Activity AnthillBot, «@AI» в чатах — `@AnthillBot`,
«Спросить ИИ» в Ctrl+K открывает окно AnthillBot. Так? (Иначе будет два помощника
с разными именами, и люди будут спрашивать, чем они отличаются.)

**В2. Модели.** Сейчас на проде ключи OpenAI (Whisper — голос) и Anthropic (тексты).
Для агента предлагаю: разбор намерений и действия — Anthropic (structured output
надёжнее), голос — OpenAI как сейчас, картинки — та же модель, что тексты. Возражений нет?

**В3. Индексация переписки.** Retrieval с ACL означает индексировать ВСЕ сообщения,
задачи и комментарии компании (эмбеддинги — платные запросы к модели, один раз на
фрагмент плюс инкрементально). На вашем объёме (~10–20 тыс. сообщений) это
разово недорого, но подтвердите, что переписку индексировать можно.

**В4. Интеграции MVP 3** — с чего начать: Google Calendar, Gmail, Google Drive?
(Календарь уже синхронизируется по .ics без OAuth — для действий «создай встречу»
понадобится OAuth Google.)

**В5. Порядок.** Начинаю с этапа 1 (MVP 1) сразу после ответов на В1–В3; В4 нужен к
этапу 3.

## Ход работ

**14.09.2026 — ответы заказчика.** В1 — да, имя одно: AnthillBot. В2 — пока **все
модели OpenAI**, ключ уже в системе. В3 — индексировать переписку можно. В4 — к
этапу 3.

**Этап 1 (MVP 1) сделан.** Модуль `anthill` на сервере: оркестратор (план → до
четырёх читающих инструментов → ответ потоком со ссылками), десять читающих
инструментов поверх существующих сервисов, два пишущих (задача, напоминание) —
только через подтверждение, с откатом. Таблицы `ai_sessions`, `ai_messages`,
`ai_tool_actions`, `ai_feedback`; история «Корпоративного разума» перелита.
Экран: `AnthillPanel` — окно поверх CRM из Chat Bar, собеседник в списке чатов,
полноэкранный `/chat/anthill`, пункт «Спросить ИИ — AnthillBot» в Ctrl+K.
Контекст страницы с выключателем, кнопки-источники, карточка действия
[Создать] [Редактировать] [Отмена] и «Отменить» после выполнения, голосовой
вопрос, история разговоров, 👍/👎 с причиной, «Остановить».

**Сознательно отложено в этап 2.**
1. Отдельная векторная индексация ВСЕЙ переписки (п. 3 этапа 1). Инструменты
   ищут через уже работающие `chats.searchMessages`, `search.all` и семантический
   поиск регламентов (`knowledge`, K1) — это те же права и ноль новых расходов на
   эмбеддинги. Отдельный индекс сообщений нужен, когда начнёт не хватать качества
   поиска по словам; тогда он ляжет в `knowledge` расширением, а не новой системой.
2. Правка карточки задачи ограничена названием, описанием и сроком: смена
   исполнителя и проекта — это выбор из списков, они приедут вместе с
   write-инструментами второй волны (update_task, set_assignee).

**Грабли.** Имя `ai_actions` уже занято журналом секретаря (0041) — таблица
агента называется `ai_tool_actions`. Один и тот же параметр запроса значением
колонки и операндом `CASE` роняет весь UPDATE («inconsistent types deduced»):
время подтверждения считаем в TS.
