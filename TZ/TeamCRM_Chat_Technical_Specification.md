# Техническое задание: модуль чатов TeamCRM

## 1. Общая цель

Необходимо доработать модуль **«Миты и мессенджеры»** в TeamCRM и привести чат-интерфейс к полноценному корпоративному рабочему инструменту.

За основу UX можно брать сильные решения Bitrix24 и Slack, но без прямого копирования интерфейса. Основная идея:

- чат должен быть доступен из любого раздела CRM;
- пользователь не должен терять текущий рабочий контекст;
- чат должен быть связан с задачами, проектами, митами и AI;
- текущий функционал мессенджера должен быть сохранён;
- новые функции не должны ломать существующие треды, сообщения, реакции, упоминания, файлы, голосовые сообщения и другие уже реализованные возможности.

---

## 2. Критическое требование: сохранить текущий функционал

При переработке интерфейса чатов **нельзя удалять, отключать или упрощать уже существующие функции**.

Должны полностью сохраниться:

- личные чаты;
- групповые чаты;
- каналы;
- треды;
- ответы на конкретные сообщения;
- реакции;
- `@упоминания`;
- непрочитанные сообщения;
- закреплённые сообщения;
- избранные сообщения;
- файлы;
- изображения;
- ссылки;
- голосовые сообщения;
- видео/медиа, если уже поддерживаются;
- поиск по сообщениям;
- создание задач из сообщений, если уже реализовано;
- AI-функции, если уже реализованы;
- история переписки;
- права доступа;
- уведомления;
- статусы пользователей;
- существующая логика митов и созвонов.

### Важно

Новый правый сайдбар, новый Chat Bar и новая структура интерфейса должны быть **надстройкой над текущей системой**, а не заменой текущей логики.

Треды особенно важны и должны работать после редизайна без изменений по бизнес-логике:

- возможность ответить на конкретное сообщение;
- отдельная ветка обсуждения;
- отображение количества ответов;
- непрочитанные ответы;
- переход к исходному сообщению;
- возможность отправить ответ в основной канал, если такая опция уже есть;
- отдельный раздел «Треды» должен сохраниться.

---

## 3. Общая архитектура интерфейса

Модуль должен состоять из трёх уровней.

### Уровень 1 — глобальный Chat Bar

Постоянная узкая правая панель, доступная практически из любого раздела CRM.

### Уровень 2 — окно текущего чата

Открывается поверх текущей страницы или в боковом слайдере, не уводя пользователя из текущего раздела CRM.

### Уровень 3 — сайдбар конкретного чата

Дополнительная панель информации о текущем чате:

- участники;
- файлы;
- ссылки;
- медиа;
- задачи;
- миты;
- избранное;
- настройки.

---

## 4. Глобальный правый Chat Bar

Chat Bar должен быть доступен из:

- досок;
- проектов;
- задач;
- клиентов;
- митов;
- календаря;
- других основных разделов CRM.

Пользователь не должен переходить в отдельный раздел только для того, чтобы написать сотруднику.

### Состояния Chat Bar

**Свёрнутый:**

- аватары;
- AI;
- уведомления;
- поиск;
- счётчики непрочитанных.

**Развёрнутый:**

- имя;
- статус;
- последнее сообщение;
- счётчик непрочитанных;
- закреплённые чаты;
- последние чаты;
- поиск.

### Рекомендуемая структура

```text
Уведомления
AI
----------------
Закреплённые
  Сергей
  TeamCRM Development
  Panorama
----------------
Последние
  Глеб
  Юрий
  Marketing
  Client Chat
----------------
Поиск
Новый чат
```

## 5. Закреплённые чаты

Пользователь должен иметь возможность закрепить:

- сотрудника;
- личный чат;
- групповой чат;
- канал;
- проектный чат;
- клиентский чат;
- чат задачи.

Закреплённые элементы всегда отображаются в верхней части Chat Bar.

Настройка должна сохраняться на уровне пользователя.

---

## 6. Последние чаты

Список последних чатов должен сортироваться по последней активности.

Для каждого элемента отображать:

- аватар;
- название;
- онлайн-статус;
- последнее сообщение;
- время;
- непрочитанные;
- `@упоминания`.

---

## 7. Онлайн-статусы

Поддержать статусы:

- онлайн;
- отошёл;
- занят;
- на мите;
- офлайн.

Пример:

```text
Глеб
На мите · 18 мин
```

или:

```text
Алина
была 12 минут назад
```

---

## 8. Поиск в Chat Bar

Поиск должен работать минимум по:

- сотрудникам;
- чатам;
- каналам;
- проектам;
- клиентам.

В дальнейшем можно расширить до глобального поиска по задачам и сообщениям.

---

## 9. Открытие личного чата

Если пользователь нажимает на сотрудника:

1. Если чат уже существует — открыть существующий.
2. Если чата нет — автоматически создать direct conversation.
3. Не показывать отдельный лишний шаг «Создать чат».

---

## 10. Окно текущего чата

Чат должен открываться в правой части интерфейса или боковом слайдере.

Текущая CRM-страница должна оставаться открытой.

```text

```

## 12. Сохранение текущего функционала сообщений

После редизайна должны работать без изменений:

- текстовые сообщения;
- редактирование;
- удаление;
- реакции;
- ответы;
- треды;
- цитирование;

- голосовые;

- системные сообщения.

## 13. Треды

### Требование

Треды не должны быть удалены или заменены новой системой чатов.

Тред является отдельной веткой, привязанной к исходному сообщению.

### Функции

- ответ на конкретное сообщение;
- отдельное окно/панель ветки;
- количество ответов;
- список участников;
- непрочитанные ответы;
- упоминания;
- файлы внутри ветки;
- AI внутри ветки;
- переход к исходному сообщению.

### Раздел «Треды»

Должен сохраниться отдельный раздел:

**Миты и мессенджеры → Треды**

Там пользователь видит:

- активные треды;
- непрочитанные ответы;
- ветки, где его упомянули;
- ветки, где он участвовал.

- связанная задача;

---

## 16. Действия по участнику

Через клик или меню `...`:

- написать лично;
- позвонить;
- упомянуть;
- открыть профиль;
- открыть задачи пользователя;
- открыть календарь;
- сделать администратором;
- удалить из чата.

Дополнительно для TeamCRM:

- посмотреть задачи пользователя в текущем проекте;
- посмотреть активные задачи;
- посмотреть связанные миты.

---

## 17. Добавление участников

Вверху блока участников:

```text
Участники 7     🔍  👤+
```

Через `👤+`:

- поиск сотрудника;
- выбор нескольких сотрудников;
- добавление отдела;
- добавление внешнего пользователя, если разрешено.

---

## 18. Внутренние и внешние участники

Внешние пользователи должны визуально отличаться.

Пример:

```text
Иван Петров
Внешний пользователь
```

Внешний пользователь должен видеть только разрешённый чат/мит и не получать доступ ко всей CRM.

- предпросмотр;

Пользователь может сохранить сообщение и потом быстро найти его в Sidebar.

## 22. Задачи в Sidebar

Показывать:

- задачи, созданные из этого чата;

- название;
- описание;
- чеклист;

## 25. Созвон из чата

Из любого личного или группового чата:

**Созвон**

Созвон должен запускаться в контексте текущего чата.

Поддержать:

- аудио;
- видео;
- демонстрацию экрана;
- запись;
- транскрибацию;
- AI Summary;
- создание задач.

---

## 26. Сворачивание активного мита

Активный мит должен сворачиваться в плавающее окно.

Пользователь должен продолжать работать:

- в CRM;
- в задачах;
- в проектах;
- в чатах.

При этом не должны прерываться:

- звонок;
- микрофон;
- камера;
- запись;
- транскрипция.

---

## 27. AI в чате

В каждом чате доступен:

```text
@AI
```

AI должен работать в контексте текущего чата.

Примеры:

- «Что решили по API?»
- «Сделай Summary последних 50 сообщений»
- «Какие задачи здесь обсуждались?»
- «Что я пропустил?»
- «Создай чеклист»

---

## 28. AI в контексте CRM

Если чат связан с:

- задачей;
- проектом;
- клиентом;
- митом;

AI может использовать этот контекст при наличии прав.

AI не должен получать доступ к данным, которые недоступны пользователю.

---

## 29. Голосовые вопросы AI

Через микрофон:

1. записать вопрос;
2. speech-to-text;
3. передать AI;
4. получить ответ;
5. отобразить ответ в чате.

---

## 30. Контекст текущей CRM-страницы

Если пользователь находится в задаче и открывает чат, добавить действие:

**+ Отправить текущую задачу**

В чат отправляется карточка задачи.

То же самое для:

- проекта;
- клиента;
- мита.

- в Chat Bar;

Необходимо визуально различать:

- обычное непрочитанное;
- `@упоминание`;
- новое сообщение в треде.

## 43. AI-контекст

AI должен получать контекст только по необходимости.

Не передавать всю историю чата на каждый запрос.

Использовать:

- последние сообщения;
- summary;
- релевантный поиск;
- текущую сущность CRM;
- связанный мит;
- права пользователя.

---

## 44. История и аудит

Фиксировать:

- создание чата;
- изменение названия;
- добавление/удаление участника;
- изменение прав;
- создание задачи из сообщения;
- запуск мита;
- закрепление важных сообщений.

---

## 45. Мобильная версия

На мобильном:

- Chat Bar превращается в отдельный экран;
- Sidebar чата открывается отдельной панелью;
- тред открывается поверх чата;
- свайп назад возвращает в чат;
- активный мит сворачивается в mini-player.

---

## 46. Производительность

При большом количестве сообщений:

- pagination / infinite scroll;
- lazy loading;
- виртуализация списка;
- загрузка медиа по необходимости;
- индексация поиска;
- оптимизация WebSocket subscriptions.

---

## 47. Безопасность

Обязательно:

- server-side проверка доступа;
- нельзя полагаться только на frontend;
- URL файлов с проверкой доступа;
- внешний пользователь не видит внутренние данные;
- AI соблюдает права текущего пользователя.

---

## 48. Backward compatibility

Критическое требование.

Нельзя выполнять миграцию таким образом, чтобы:

- старые сообщения исчезли;
- треды потеряли связи;
- файлы перестали открываться;
- реакции пропали;
- старые чаты перестали работать;
- ID существующих чатов изменились без необходимости.

При необходимости использовать migration layer.

## 51. Итоговая концепция

TeamCRM Chats должен стать не отдельным мессенджером внутри CRM, а **единым коммуникационным слоем всей системы**.

```text
CRM
├── Projects
│   └── Project Chat
├── Tasks
│   └── Task Chat
├── Clients
│   └── Client Chat
├── Meetings
│   └── Meeting / Summary
└── Messenger
    ├── DM
    ├── Groups
    ├── Channels
    ├── Threads
    └── AI
```

Основной принцип:

> Пользователь может находиться в любом месте CRM, открыть чат справа, написать сотруднику, открыть тред, начать мит, создать задачу из сообщения, спросить AI и затем продолжить работу в том же месте CRM.

При этом **весь существующий функционал мессенджера должен сохраниться и продолжить работать после внедрения новой архитектуры**.
