# ТЗ-4 · Импорт «в один клик»

**Обещание маркетинга:** «Переезд со старой системы за 60 секунд, без потери задач и
переписок». Обещание обязано быть правдой, иначе оно работает против нас: человек
попробует, потеряет полдня и расскажет об этом.

**Почему это важнее половины остальных фич.** Команда не выбирает таск-менеджер —
она выбирает переезд. Пока перенос данных делается руками, ответ «система супер, но у
нас всё в Битриксе/Notion» закрывает разговор. Импорт — не удобство, а условие входа.

---

## 1. Что уже есть

| Источник | Состояние | Что переносит |
|---|---|---|
| **Битрикс24** | E1–E3 на staging | проекты, колонки, задачи, комментарии, теги, вложения → MinIO, лента; живая синхронизация по вебхукам |
| **YouGile** | E1–E4, E1–E3 на проде | доски → проекты, колонки, задачи, комментарии (чат), вложения, маппинг людей, вебхуки |
| **Google Docs** | сканер базы знаний | документы → база знаний (RAG) |

Общее у обоих готовых импортов: подключение (ключ/вебхук) → выбор досок → фоновый
прогон с прогрессом → идемпотентный upsert по внешнему id → ручная привязка людей.
**Этот путь и есть каркас: новые источники добавляются в него, а не рядом с ним.**

## 2. Что делаем (порядок выбран заказчиком)

### Слой 1 — CSV/Excel (сделан)

Универсальный вход: из него грузится что угодно, включая выгрузки Trello, Notion,
Asana, Jira и любые самописные таблицы. Не требует ключей, согласий и живого доступа
к чужой системе — работает всегда, и потому идёт первым.

- Файл `.csv` или `.xlsx` (до 10 МБ, до 5000 строк за прогон).
- Разбор БЕЗ новых зависимостей: CSV — свой разборщик, XLSX — через `jszip`
  (xlsx и есть zip с XML). Кодировка определяется сама: русский Excel сохраняет CSV
  в windows-1251 с точкой с запятой, и без этого файл превращается в «Ð—Ð°Ð´Ð°Ñ‡Ð°».
- Сопоставление колонок — с автоугадыванием по заголовкам («Задача», «Исполнитель»,
  «Срок», «Due date», «Assignee»…), но последнее слово за человеком.
- Предпросмотр ДО записи: сколько строк, кто из людей не опознан, что будет пропущено.
- Люди сопоставляются по почте, затем по имени; неопознанные не роняют импорт —
  задача создаётся без исполнителя и попадает в список предупреждений.

### Слой 2 — Trello

По ключу API или по JSON-выгрузке доски (`Показать меню → Ещё → Печать и экспорт`).
Выгрузка предпочтительнее: не требует согласия администратора рабочего пространства.
Переносим: списки → колонки, карточки → задачи, чек-листы, метки, вложения,
комментарии, участники.

### Слой 3 — Notion

По ключу интеграции. База данных со статусами → доска: `Status`/`Select` становится
колонками, страницы — задачами, содержимое страницы — описанием (Markdown).
Тонкость: у Notion нет понятия «доска» — есть база данных с представлением, и
выбирать человек будет именно базу.

### Слой 4 — Google-документы

Папка Google Drive → база знаний и описания задач. Частично есть (сканер),
не хватает кнопки и выбора папки. Требует OAuth-приложения и согласия.

## 3. Общее для всех источников

- **Один экран «Импорт»** в настройках: плитки источников, история прогонов, отчёт.
- **Прогон = запись в базе** с состоянием (`queued/running/done/error`), счётчиками и
  списком предупреждений. Импорт без отчёта — это лотерея.
- **Идемпотентность.** Повторный прогон не плодит дубли: у внешних систем — по
  внешнему id, у файла — по колонке с идентификатором, если она есть; если её нет,
  повтор честно предупреждает «будут созданы новые задачи».
- **Ничего не удаляем.** Импорт только добавляет и обновляет: чужая выгрузка не
  должна уметь стереть нашу работу.
- **Люди.** Сопоставление по почте → по имени → руками. Неопознанный человек никогда
  не молчит: он в отчёте.

## 4. Границы

Не переносим (и говорим об этом прямо): историю изменений чужой системы, права
доступа, автоматизации и роботов, «умные» поля вроде формул. Перенос переписки —
только там, где она есть в API (Битрикс, YouGile, Trello-комментарии).
