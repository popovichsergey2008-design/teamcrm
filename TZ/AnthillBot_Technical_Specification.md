# Техническое задание: AnthillBot для TeamCRM

## 1. Общая концепция

Необходимо разработать встроенного системного AI-бота **AnthillBot** для TeamCRM по аналогии с современным Slackbot.

AnthillBot должен быть не просто чат-ботом, а **персональным AI-агентом внутри CRM**, который:

- понимает рабочий контекст пользователя;
- отвечает на вопросы по данным TeamCRM;
- ищет информацию в чатах, проектах, задачах, митах и файлах;
- помогает готовить документы, сводки, чеклисты и постановки задач;
- выполняет разрешённые действия в CRM;
- создаёт напоминания и регулярные автоматические задачи;
- работает с персональной памятью пользователя;
- поддерживает навыки / сценарии;
- может использовать внешние интеграции;
- строго соблюдает права доступа;
- всегда показывает источник данных и не выдаёт предположения за факты.

AnthillBot должен быть встроен в существующий модуль **«Миты и мессенджеры»**, но при этом иметь собственный системный чат и возможность работать из любого контекста CRM.

Пользователь должен иметь возможность написать AnthillBot:

- «Что мне сегодня нужно сделать?»
- «Какие задачи просрочены?»
- «Что я пропустил в TeamCRM за вчера?»
- «Что решили на последнем мите по проекту Panorama?»
- «Найди, где Глеб писал про ошибку API».
- «Составь краткий отчёт по проекту за неделю».
- «Подготовь повестку на мит завтра».
- «Создай задачу Глебу по этому обсуждению».
- «Напомни мне завтра проверить эту задачу».
- «Каждый понедельник готовь мне сводку по просроченным задачам».
- «Сделай чеклист по этой задаче».
- «Объясни мне, что от меня требуется».
- «Сравни две задачи и скажи, не дублируются ли они».
- «Найди похожие задачи».
- «Сформируй summary последних 100 сообщений».
- «Сделай отчёт по всем задачам, которые я поставил за неделю».

# 3. Размещение AnthillBot

AnthillBot должен быть доступен минимум из трёх мест.

## 3.1. Отдельный системный чат

В разделе:

**Миты и мессенджеры → AnthillBot**

AnthillBot отображается как отдельный системный контакт.

Пример:

```text
AnthillBot
AI-помощник TeamCRM
```

---

## 3.2. Глобальная кнопка AI

В глобальном правом Chat Bar должна быть отдельная кнопка:

```text
🤖 AnthillBot
```

По нажатию открывается компактное окно AnthillBot поверх текущей CRM-страницы.

---

## 3.3. Полноэкранный режим

Для больших задач необходим режим:

**Открыть AnthillBot на весь экран**

Используется для:

- длинных аналитических запросов;
- исследования проекта;
- подготовки отчёта;
- работы с большими файлами;
- deep research;
- просмотра истории запросов.

---

# 4. Работа в контексте текущей страницы

AnthillBot должен понимать, где находится пользователь.

Если пользователь открыт в:

- задаче;
- проекте;
- клиенте;
- чате;
- треде;
- мите;
- Summary;
- доске;

AnthillBot должен иметь возможность использовать этот контекст.

Пример:

Пользователь открыт в задаче и пишет:

> Что здесь нужно сделать?

AnthillBot понимает текущую задачу без необходимости повторно вставлять ссылку.

# 8. Ответы с источниками

Каждый ответ, основанный на данных CRM, должен по возможности содержать ссылки на источник.

Пример:

```text
По проекту Panorama было принято 3 ключевых решения:

1. Перенести AI-чат в карточку задачи.
   [Открыть сообщение]

2. Добавить фильтр «От меня».
   [Открыть задачу #1422]

3. Добавить ссылки на задачи в Summary.
   [Открыть мит]
```

AnthillBot не должен выдавать выдуманные ссылки, задачи, проекты или пользователей.

Если источник не найден:

```text
Я не нашёл подтверждения этой информации в доступных данных TeamCRM.
```

# 9. Summary и «Что я пропустил»

AnthillBot должен уметь делать краткие сводки.

Примеры:

- «Что я пропустил сегодня?»

- «Что изменилось в этой задаче?»
- «Что обсуждали в чате после моего последнего просмотра?»

Ответ должен группироваться по смыслу:

```text
Проект TeamCRM

Решения:
- ...

Новые задачи:
- ...

Проблемы:
- ...

Требует вашего внимания:
- ...
```

# 11. Создание задач через AnthillBot

AnthillBot должен создавать задачи из естественного языка.

Пример:

> Создай Глебу задачу по последнему обсуждению API до пятницы.

AnthillBot должен:

1. найти контекст;
2. сформировать название;
3. сформировать краткое грамотное описание;
4. создать чеклист;
5. определить исполнителя;
6. определить дедлайн;
7. определить проект;
8. показать preview;
9. запросить подтверждение;
10. создать задачу.

По умолчанию:

**«Не завершать без согласования с постановщиком» — включено.**

# 12. Подтверждение действий

AnthillBot не должен выполнять критические изменения без подтверждения пользователя.

Требуют подтверждения:

- создание задачи;
- изменение задачи;
- закрытие задачи;
- удаление;
- изменение исполнителя;
- отправка сообщения от имени пользователя;
- добавление/удаление человека из чата;
- изменение статуса;
- изменение дедлайна;
- архивирование;
- массовые действия.

Пример:

```text
Создать задачу?

Название: Исправить API авторизации
Исполнитель: Глеб
Срок: 18.09.2026
Проект: TeamCRM

[Создать] [Редактировать] [Отмена]
```

# 16. Skills / Навыки AnthillBot

Необходимо предусмотреть систему навыков.

Навык — заранее описанный пошаговый сценарий для сложной повторяющейся работы.

Примеры:

- «Еженедельный отчёт проекта».
- «Подготовка к клиентскому миту».
- «Создание задачи разработчику».
- «Проверка просроченных задач».
- «Подготовка релизного отчёта».
- «Онбординг нового сотрудника».

Навык содержит:

```text
Название
Описание
Когда использовать
Шаги
Входные данные
Ожидаемый результат
Доступные действия
```

# 41. Продолжение старого диалога

Пользователь может открыть старую сессию и продолжить:

> Продолжи тот отчёт, который мы делали вчера.

Контекст сессии должен сохраняться.

---

# 42. Новый чат

Кнопка:

**+ Новый разговор**

Создаёт чистый контекст AnthillBot, не смешивая прошлую тему.

---

# 43. Отмена генерации

Во время длинного ответа должна быть кнопка:

**Остановить**

Остановка не должна удалять уже сформированную часть ответа.

---

# 44. Редактирование запроса

Пользователь должен иметь возможность:

- отредактировать предыдущий prompt;
- повторить;
- создать новый branch.

---

# 45. Feedback

Для ответа AnthillBot:

```text
👍  👎
```

При отрицательной оценке:

- неточно;
- не нашёл данные;
- придумал факт;
- не тот контекст;
- плохая формулировка;
- другое.

Это необходимо для улучшения prompts, retrieval и качества модели.

---

# 46. Защита от галлюцинаций

Если AnthillBot не уверен:

```text
Мне недостаточно данных, чтобы подтвердить это.
```

Нельзя придумывать:

- ID задач;
- пользователей;
- сроки;
- решения;
- ссылки;
- сообщения;
- проекты.

Для ключевых фактов желательно отображать источник.

---

# 47. Permissions First

Перед retrieval и перед каждым действием:

```text
user_id
→ roles
→ CRM permissions
→ entity permissions
→ allowed data
→ AI context
```

Не допускается схема:

```text
AI получил все данные
→ потом решил, что показывать
```

Фильтрация должна происходить ДО передачи контекста в модель.

---

# 48. Tool / Action Layer

LLM не должен напрямую изменять БД.

Архитектура:

```text
User
  ↓
AnthillBot Orchestrator
  ↓
Intent / Planning
  ↓
Permission Check
  ↓
Tools
  ├── search_tasks
  ├── get_task
  ├── create_task
  ├── update_task
  ├── search_messages
  ├── get_meeting
  ├── create_reminder
  └── ...
  ↓
Result
  ↓
AnthillBot
```

---

# 49. Structured Output

Для действий модель должна возвращать структурированные параметры.

Пример:

```json
{
  "action": "create_task",
  "requires_confirmation": true,
  "params": {
    "title": "Исправить авторизацию API",
    "assignee_id": 17,
    "project_id": 4,
    "deadline": "2026-09-18",
    "priority": "high",
    "requires_creator_approval": true,
    "checklist": [
      "Воспроизвести ошибку",
      "Найти причину",
      "Исправить",
      "Протестировать"
    ]
  }
}
```

---

# 50. Логи действий

Все изменения AnthillBot необходимо логировать.

Сохранять:

- пользователь;
- команда;
- tool;
- параметры;
- подтверждение;
- результат;
- дата;
- ошибка.

---

# 51. Undo / отмена действия

Для безопасных действий желательно поддержать:

```text
Задача создана.
[Открыть] [Отменить]
```

Undo доступен там, где технически возможно.

---

# 52. Администрирование AnthillBot

Администратор должен иметь возможность:

- включить / отключить AnthillBot;
- определить группы пользователей;
- включить web search;
- включить работу с файлами;
- разрешить actions;
- разрешить внешние интеграции;
- управлять skills;
- управлять custom responses;
- видеть usage;
- видеть системные ошибки.

---

# 53. Ограничения и квоты

Необходимо предусмотреть configurable limits:

- количество запросов;
- размер контекста;
- deep research;
- размер файлов;
- количество scheduled tasks;
- количество Skills;
- web search.

Не привязывать архитектуру к конкретным коммерческим лимитам Slack.

---

# 54. Модель / LLM

LLM слой должен быть абстрагирован.

AnthillBot не должен быть жёстко связан с одной моделью.

Пример:

```text
LLMProvider
├── OpenAI
├── Anthropic
├── Google
└── Local / future
```

Для разных задач можно использовать разные модели.

---

# 55. RAG / Retrieval

Для поиска по CRM нужен отдельный retrieval layer.

Индексировать:

- messages;
- threads;
- tasks;
- projects;
- summaries;
- transcripts;
- documents;
- comments.

Обязательно хранить ACL metadata для каждого фрагмента.

---

# 56. Работа с большими чатами

Не передавать весь чат в LLM.

Использовать:

1. query;
2. semantic + keyword retrieval;
3. permission filtering;
4. relevant chunks;
5. recent context;
6. summary;
7. LLM.

---

# 64. Ошибки

AnthillBot должен показывать понятные ошибки.

Не:

```text
AI_ERROR_500
```

А:

```text
Не удалось получить данные проекта.
Попробовать снова
```

Для actions:

```text
Не удалось создать задачу. Ваши данные сохранены.
[Повторить]
```

# 68. Ключевой принцип продукта

AnthillBot должен быть не просто «ChatGPT внутри CRM».

Правильная модель:

```text
LLM
+
TeamCRM Context
+
Search
+
Permissions
+
Memory
+
Skills
+
Actions
+
Scheduled Tasks
+
Meetings
+
Chats
+
Projects
+
Tasks
```

Именно эта связка превращает AnthillBot в **персонального AI-агента TeamCRM**, который не только отвечает, но и реально помогает выполнять работу.
