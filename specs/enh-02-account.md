# Enhancements v1 — Этап C. Личный кабинет пользователя

> Часть [трека улучшений](enh-00-master.md). Зависит от Этапа A (аватар → файлы) и Этапа B (должность как поле профиля).

## Цель

Дать пользователю самостоятельно управлять своим аккаунтом: профиль, смена пароля, аватар, настройки уведомлений, собственная доступность (отпуска/больничные/ёмкость), безопасность (активные сессии, выход со всех устройств, опционально 2FA).

## Текущее состояние

`GET /api/me` отдаёт профиль (без редактирования). Пароль меняется только пересозданием. `refresh_tokens` хранит сессии (token_hash/expires_at/revoked_at) — основа для списка сессий. `user_availability` (Этап 4) есть, но без self-service эндпоинтов. Нет аватара, телефона, таймзоны, настроек уведомлений.

## Доменная модель (DDL — миграция `0008`)

```sql
ALTER TABLE users
    ADD COLUMN avatar_file_id BIGINT NULL REFERENCES files(id),
    ADD COLUMN phone          VARCHAR(32) NULL,
    ADD COLUMN timezone       VARCHAR(48) NOT NULL DEFAULT 'Europe/Moscow',
    ADD COLUMN locale         VARCHAR(8)  NOT NULL DEFAULT 'ru',
    ADD COLUMN notify_prefs   JSONB NOT NULL DEFAULT '{}'::jsonb;   -- каналы/типы уведомлений

-- Метка сессии для списка устройств (дополняет refresh_tokens).
ALTER TABLE refresh_tokens
    ADD COLUMN user_agent VARCHAR(255) NULL,
    ADD COLUMN ip         VARCHAR(64)  NULL,
    ADD COLUMN last_used_at TIMESTAMPTZ NULL;
```

## Контракты

### Профиль
- `GET /api/me` расширяется: должность, аватар-URL, телефон, таймзона, локаль, группы, ёмкость.
- `PATCH /api/me` — редактирование своих полей: `full_name`, `phone`, `timezone`, `locale` (e-mail и роль — НЕ через self-edit; e-mail-смена — отдельный verified-флоу, вне scope; роль меняет только admin).

### Смена пароля
- `POST /api/me/password` — `{ currentPassword, newPassword }`; проверка текущего (argon2.verify); хэш нового; **отзыв всех refresh-сессий, кроме текущей** (безопасность); валидация сложности (≥8).

### Аватар
- `POST /api/me/avatar` (multipart) → через модуль `files` (Этап A), `owner_kind='avatar'` → `users.avatar_file_id`. `GET /api/me` отдаёт URL `/api/files/{id}`. Удаление аватара — сброс поля.

### Уведомления и доступность
- `PUT /api/me/notifications` — `notify_prefs` (JSON: какие события, какие каналы — пока in-app/Telegram, e-mail позже).
- `GET/POST/DELETE /api/me/availability` — собственные отпуска/больничные (использует `user_availability` Этапа 4; влияет на ёмкость/прогноз). Ёмкость (`weekly_capacity_hours`) — просмотр; правка — admin (это плановый параметр).

### Безопасность (сессии / 2FA)
- `GET /api/me/sessions` — список активных refresh-сессий (устройство/IP/последняя активность/текущая).
- `DELETE /api/me/sessions/{id}` — отозвать конкретную сессию; `POST /api/me/sessions/revoke-all` — выйти со всех, кроме текущей.
- **2FA — исключено из scope** (по решению заказчика 2026-06-30). Может вернуться отдельным под-этапом позже.

## Frontend

- Раздел **«Профиль»** (по клику на имя/аватар в шапке): форма профиля, загрузка аватара, смена пароля.
- Раздел **«Уведомления»**: переключатели типов событий.
- Раздел **«Доступность»**: список своих отпусков/больничных + добавление; просмотр недельной ёмкости.
- Раздел **«Безопасность»**: список сессий с кнопками отзыва, «выйти со всех»; блок 2FA (QR + включение/выключение).
- Аватар отображается в шапке и на карточках (assignee), в списке команды.

## Этапы работ

- **C.1.** Миграция `0008`; расширение `GET /api/me` и `PATCH /api/me`.
- **C.2.** Смена пароля с отзывом прочих сессий; валидация.
- **C.3.** Аватар через модуль `files`; отображение в шапке/командах/карточках.
- **C.4.** Уведомления (`notify_prefs`) + self-service доступности.
- **C.5.** Безопасность: список/отзыв сессий (на `refresh_tokens` + метаданные). (2FA исключена из scope.)
- **C.6.** Frontend: разделы Профиль/Уведомления/Доступность/Безопасность; аватары в UI.
- **C.7.** Тесты: unit (валидация пароля, сериализатор профиля без секретов), e2e (правка профиля, смена пароля→старые сессии отозваны, загрузка аватара, отзыв сессии), security (нельзя править чужой профиль; пароль-хэш/totp_secret не отдаются в API).

## DoD этапа C

Пользователь редактирует свой профиль, меняет пароль (прочие сессии отзываются), загружает аватар, настраивает уведомления и доступность, видит и отзывает сессии; 2FA включается/выключается; секреты (password_hash, totp_secret) не утекают в API; e2e и security-тесты зелёные.

## Тесты (минимум)

| Группа | Кейсы |
|---|---|
| профиль | PATCH меняет свои поля; нельзя сменить роль/чужой профиль; e-mail/роль не редактируются self |
| пароль | неверный текущий → ошибка; смена отзывает все прочие refresh-сессии; новый пароль работает |
| аватар | загрузка → `avatar_file_id` проставлен, URL отдаётся; чужой файл недоступен |
| сессии | список показывает активные; отзыв сессии делает её refresh невалидным; revoke-all не трогает текущую |
